# Workflow Runtime 扩大 A/B 评测结果

## 当前可复核结论

截至本次提交，已完成 3 个独立随机种子分组。每组包含 30 类差异化任务、2 次重复和 `guard/reuse` 两个实验臂，共 120 Job；三组合计 360 Job。

| 组 | Seed | Guard 最终通过 | Reuse 最终通过 | 整组 |
|---|---:|---:|---:|---:|
| G1 | 20260817 | 60/60 | 60/60 | 120/120 |
| G2 | 20260820 | 60/60 | 60/60 | 120/120 |
| G3 | 20260821 | 60/60 | 60/60 | 120/120 |
| 合计 | — | 180/180 | 180/180 | 360/360 |

最终性能架构 `reuse` 在当前 180 个样本上的评测集闭环成功率为 100%，95% Wilson 区间约为 97.9%–100%。该结论限定于本任务集、Pi + DeepSeek、固定预算和独立 Verifier，不等于所有未知任务的理论成功率为 100%。

## 历史性能汇总（不进入正式指标）

旧评测只提交了逐组汇总，没有保留 360 个 Job 的逐条时延、Token、请求、重试与 Session 复用明细；执行顺序也是整组 Guard 与整组 Reuse 随机，而不是同任务两臂相邻。以下数字可用于定位下一轮测试，不能证明 Session 复用的正式性能收益：

| 指标 | Guard | Reuse | 变化 |
|---|---:|---:|---:|
| 180 Job 总 Token | 8,336,096 | 5,957,878 | -28.5% |
| Issue P50 | 32.0s | 25.8s | -19.4% |
| Issue P95 | 107.1s | 116.9s | +9.2% |

正式性能指标暂不发布。新一轮必须保留逐 Job 配对明细和运行指纹，Guard/Reuse 按同一任务相邻执行并随机先后顺序；缺对、重复、跨环境、跨版本、断点续跑混入、请求数不一致或 Session 复用序列异常时整轮拒绝。验收至少覆盖 300 对任务、5 个独立 Seed，使 P95 以上至少有 15 个观测点；所有配对任务完成状态一致后，才发布 Token、P50、P95 及配对 Bootstrap 95% 置信区间。

## 与原始架构对照

同一套修正后任务与 Verifier 的原始架构基线为 40/60（66.7%）。新 Runtime 增加权威状态机、独立 Verification、结构化失败证据、两次有界 Attempt、进度守护和 fenced late-result rejection；最终性能架构再叠加单 Issue Session/Workdir 与上下文快照复用。

旧评测曾得到 95%。复盘证明其中存在评测假阴性：CSV Verifier 的 JSON 双引号转义会拒绝正确实现，另一个 Verifier 只返回 `Error: base`，无法指导恢复。此次修复没有放宽验收、没有增加第三次重试，也没有人工干预；新增回归测试后，原失败集定向复测 20/20 通过，随后才进入扩大评测。
